# Gemini Canvas Generation Guardrails

## Purpose

本文件用于在正式编写 `Gemini Canvas` prompt 前，先锁定“模型最容易跑偏的点”。

原则：

- 先写硬边界，再写生成 prompt
- 这份文件比 prompt 更短、更硬
- 每次生成前先确认这 5 类约束是否写清

## Guardrail Checklist

### 1. Main Storyline

- 本次主演示线是什么
- 哪个场景必须最优先出现
- 哪个页面是主说服页

示例：

- 主线：订单池 -> 运输规划 -> 承运商推荐 -> 确认指派 -> 任务结果
- 主场景：国内工厂到工厂内贸运输
- 核心页：承运商推荐页

### 2. Side Branch Limit

- 支线场景是什么
- 支线最多展示到什么程度
- 哪些页面不能让支线抢主线

示例：

- 支线：前程陆运说明
- 边界：只作为规则说明，不形成独立流程
- 不抢主线页面：页面 1、页面 2、页面 4

### 3. Non-Negotiable Display Rules

- 哪些内容不能平级展示
- 哪些候选只能做次级候选或风险候选
- 哪些信息必须保留，但只能放次级说明层

示例：

- 未通过截关/时效校验的候选不得与默认推荐候选平级展示
- 系统联动、回写、执行跟踪只能做次级信息

### 4. Tone And Language

- 页面文案偏什么风格
- 禁止出现什么类型的叙事

示例：

- 风格：业务评审可理解的货主调度决策页面
- 避免：大平台、大中台、大优化系统、大执行指挥中心叙事

### 5. Stop Conditions

- 什么情况下就停止继续修 prompt

示例：

- 主场景不再跑偏
- 核心页可信度成立
- 结果页不扩成执行系统页

## Usage Rule

- 只有在本文件 5 类约束都写清后，才进入 `Gemini Canvas` prompt 编写阶段
- 若生成结果反复跑偏，先回到本文件补硬边界，不要只叠加修正 prompt
