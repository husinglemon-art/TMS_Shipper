- 负责人：Bale

## 2. 核心对齐

### 2.1 业务目标
- 当前要解决的问题：在国内陆运场景下，货主侧对整车/零担订单仍依赖人工调度和经验判断，导致承运商协同复杂、线路选择不透明、运输安排效率低。
- 预期业务结果：围绕整车（FTL）和零担（LTL）运输，优先提升货主侧在工厂到工厂内贸运输场景下的编排效率和指派准确性；出海前程陆运仅作为说明性支线场景。
- 成功指标：承运商指派效率提升、推荐依据更清楚、工厂到工厂订单转运输任务的效率提升。

### 2.2 用户路径
- 入口：订单从 ERP/WMS 同步进入系统，货主调度员开始运输编排。
- 主流程：订单导入 -> 订单池/待规划列表 -> 运输规划 -> 承运商推荐或竞价 -> 确认指派 -> 运输任务生成。
- 结束状态：货主侧生成运输任务并明确承运关系，形成可继续执行的运输安排。

### 2.3 范围与边界
- 本次包含：国内陆运订单管理、整车/零担规划判断、承运商选择与任务指派、货主侧权限隔离。
- 本次不包含：完整 ERP/WMS 设计、货代或承运商独立使用后台、司机端完整执行系统、签收回单闭环、费率对账闭环、长期 BI 经营分析大盘。

### 2.4 风险与限制
- 依赖：ERP/WMS 同步接口、承运商协同流程资料、合同费率规则资料、在途状态回传能力。
- 限制：当前输入材料更偏模块设计全案，当前版本仍需保持 demo 范围克制，不主动展开执行闭环和财务闭环。
- 待确认问题：多货主隔离是组织级隔离还是租户级隔离；承运商与司机信息是通过协同回传，还是通过轻量外链/消息反馈承接。

## 4. 小结

- 当前问题定义：这是一个面向货主侧用户的国内陆运运输管理方案，核心价值在于围绕整车/零担运输，把工厂到工厂订单快速转成可执行运输任务。
- 当前待决事项：多货主隔离边界如何表达；承运商与司机信息承接方式如何设计；结果页的后续承接提示粒度到什么程度最合适。
- 当前场景锁定：本次 `v1.0` 主场景锁定为工厂到工厂内贸运输；出海前程陆运只作为说明性支线，不作为主演示主线。
- 当前闭环锁定：本次 `v1.0` 不是完整蓝图，而是聚焦“订单到承运商指派”的核心闭环 demo。
