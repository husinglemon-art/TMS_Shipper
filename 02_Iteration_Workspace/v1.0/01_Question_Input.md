# 01 需求访谈记录

- 项目名称：货主版运输管理系统（Shipper TMS）
- 版本号：v1.0
- 日期：2026-05-20
- 负责人：Bale

## 2. 核心对齐

### 2.1 业务目标
- 当前要解决的问题：货主侧运输管理依赖人工调度、分散跟踪和低效对账，导致承运商协同复杂、运输成本高、在途异常不可控、结算误差大。
- 预期业务结果：通过订单流、信息流和资金流的一体化管理，提升运输透明度、调度效率和财务结算准确性。
- 成功指标：承运商指派效率提升、在途异常发现更及时、回单闭环更快、账单核算误差下降。

### 2.2 用户路径
- 入口：订单从 ERP/WMS 同步进入系统，货主调度员开始运输编排。
- 主流程：订单导入 -> 订单池/待规划列表 -> 运输规划 -> 承运商推荐或竞价 -> 确认指派 -> 运输任务生成。
- 结束状态：货主侧生成运输任务并明确承运关系，形成可继续执行的运输安排。

### 2.3 范围与边界
- 本次包含：订单管理、运输规划、承运商选择与任务指派、在途监控、电子签收、费率与账单管理、货主侧权限隔离。
- 本次不包含：完整 ERP/WMS 设计、货代或承运商独立使用后台、司机端完整执行系统、复杂商业化 SaaS 多租户产品化细节、长期 BI 经营分析大盘。

### 2.4 风险与限制
- 依赖：ERP/WMS 同步接口、承运商协同流程资料、合同费率规则资料、在途状态回传能力。
- 限制：当前输入材料更偏模块设计全案，尚未明确版本切片、MVP 边界和 demo 展示优先级。
- 待确认问题：本次 v1.0 是做完整蓝图还是先聚焦某个核心闭环 demo；多货主隔离是组织级隔离还是租户级隔离；承运商与司机信息是通过协同回传，还是通过轻量外链/消息反馈承接。

## 4. 小结

- 当前问题定义：这是一个面向货主侧用户的运输管理系统方案，核心价值在于通过智能编排和承运商指派决策，把订单快速转成可执行的运输任务。
- 当前待决事项：是否展示竞价/招标分支；运输任务生成后是否补一个轻量后续跟踪入口；承运商推荐区最终采用卡片对比还是列表对比。
- 当前场景锁定：本次 `v1.0` 主场景锁定为工厂到工厂内贸运输；出海前程陆运只作为说明性支线，不作为主演示主线。
- 当前受众锁定：本次 demo 主要面向货主侧业务部门负责人 / 物流管理负责人。
