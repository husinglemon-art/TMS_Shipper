## 3. 演示说明

### 3.1 本次 demo 目标

- 验证货主侧用户是否能顺着同一条主线完成“订单导入 -> 运输规划 -> 承运商指派 -> 生成运输任务”。
- 验证承运商推荐是否能展示出可信的决策依据，而不是只是点选列表。

### 3.2 建议演示顺序

1. 从订单池进入，说明订单如何进入待规划状态。
2. 进入运输规划页，说明为什么需要先做合单、拆单或路线判断。
3. 展示承运商推荐区，重点讲清成本、时效、运力可用性三类依据。
4. 确认指派后，进入运输任务生成结果页，说明闭环已经成立。

### 3.3 本次必须强调的点

- 这是货主控制塔视角，而不是承运商执行视角。
- 承运商推荐不是拍脑袋，而是有明确依据。
- demo 重点在“决策闭环”，不是“执行闭环”。

### 3.4 本次暂不展开的点

- 司机端执行流程
- 在途监控完整过程
- 签收回单闭环
- 费率对账闭环

### 3.5 当前待定问题

- 是否展示招标/竞价分支，还是只展示协议承运商推荐分支
- 运输任务生成后是否追加一个轻量的“后续可跟踪”提示入口
- 承运商推荐区是用卡片对比还是列表对比更适合 demo
