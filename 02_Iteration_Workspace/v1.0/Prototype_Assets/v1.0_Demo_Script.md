# v1.0 Demo Script

## Demo Goal

- 用一条完整主线演示货主调度员如何把订单从待规划状态推进到承运商指派完成
- 让评审方看见推荐依据、排序逻辑和任务生成结果，而不是只看到页面跳转
- 控制范围在国内陆运决策闭环，不扩展到执行闭环

## Demo Opening

本次 demo 聚焦货主侧用户如何在国内陆运场景下，把订单快速规划并指派给合适承运商。

建议开场口径：

- 本次只讲货主控制塔视角下的国内陆运订单编排与承运商指派
- 主线锁定工厂到工厂运输，整车作为主演示线，零担作为同页对照说明
- 出海前程陆运只展示规则兼容能力，不单独展开完整流程

## Recommended Talk Track

### 1. 订单进入系统
- 说明订单如何从 ERP/WMS 进入订单池
- 强调这些订单已经处于“待规划”状态
- 强调调度员看到的是统一入口，而不是分散在多个系统中处理

建议讲解句式：

- 这些订单已经同步进入待规划池，调度员先在一个入口完成筛选和优先级判断

### 2. 进入整车/零担规划
- 说明为什么货主不能直接点选承运商
- 强调整车主线和零担对照区块的分层表达
- 强调系统先做规划判断，再进入推荐，是为了避免直接靠经验拍板

建议讲解句式：

- 这里不是直接挑承运商，而是先判断这批订单更适合整车直发还是零担补位

### 3. 查看承运商推荐
- 重点讲：推荐不是拍脑袋
- 重点展示：KPI、报价、市场参考价、报价偏差、排序切换
- 先展示默认综合评分排序，再切换到报价或时效排序，让听众看到规则差异

建议讲解句式：

- 系统默认给出综合推荐，但调度员仍然可以从价格、时效或 KPI 角度重新审视候选承运商

### 4. 确认指派
- 强调货主调度员的最终决策权
- 强调二次确认是为了降低误指派风险
- 补一句：确认动作不是形式化弹窗，而是最后一次核对订单、承运商和关键时效承诺

建议讲解句式：

- 最终决定权仍在调度员，系统负责把依据给足，而不是替人完全拍板

### 5. 运输任务生成结果
- 强调本次闭环已经成立
- 提示后续可继续进入执行跟踪，但本次不展开执行闭环

建议讲解句式：

- 到这里，订单已经形成正式运输任务，后续执行可以继续跟踪，但不属于本次 demo 范围

## Suggested Page-by-Page Focus

| 页面 | 必讲内容 | 不必展开 |
| :--- | :--- | :--- |
| 订单池 / 待规划列表 | 订单来源、待规划状态、筛选项、 FTL/LTL 标签 | 数据同步技术细节 |
| 运输规划页 | 规划判断逻辑、整车主线、零担对照 | 复杂算法过程 |
| 承运商推荐区 | 推荐依据、排序切换、推荐原因 | 全量评分模型公式 |
| 确认指派 / 结果页 | 二次确认、任务生成结果、后续入口 | 执行端流程 |

## Side Branch Talk Track

- 前程陆运只作说明性支线
- 说明方式优先采用场景标签、说明文案或推荐原因提示
- 关键规则必须讲清：先校验截关时间，再看价格和其他指标
- 若候选承运商赶不上截关，即使报价更低，也不能作为默认优先推荐

## Scope Guardrails

- 不展开司机执行端
- 不展开在途监控完整流程
- 不展开签收回单闭环
- 不展开费率对账闭环

## Side Note

- 前程陆运只作说明性支线
- 关键规则：必须校验截关时间是否满足
