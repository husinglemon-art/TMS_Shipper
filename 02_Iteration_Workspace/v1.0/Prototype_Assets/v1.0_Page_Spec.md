# v1.0 Page Spec

## Purpose

本文件用于把 `v1.0` demo 的 4 个主页面拆成可直接落图的页面规格说明。

使用目标：

- 作为线框图或高保真页面的直接输入
- 作为讲解脚本和页面内容文案的承接层
- 约束页面结构，避免后续落图时范围漂移

## Global Principles

- 页面顺序必须服务于“订单到承运商指派闭环”
- 主场景锁定工厂到工厂内贸运输
- FTL 作为主演示线，LTL 只作同页对照说明
- 前程陆运只作说明性支线，不扩成独立页面
- 页面重点在货主调度员的决策闭环，而不是司机执行闭环

## Global Layout Guidance

- 顶部区域：页面标题、当前位置、关键筛选或全局动作
- 主内容区：围绕当前决策任务组织信息，避免无关模块抢占注意力
- 右侧或底部动作区：放置当前页面的主动作，保证演示时操作路径清晰
- 状态反馈区：加载、异常、空状态、成功状态要显著可见

## Page 1: 订单池 / 待规划列表

### Page Goal

- 让听众理解订单如何进入待规划状态
- 让调度员快速识别哪些订单可以进入规划主线

### Demo Role

- 这是演示入口页
- 负责建立订单来源、订单状态和运输类型的基础认知

### Suggested Layout

- 顶部：页面标题、订单来源提示、筛选区
- 中部：待规划订单列表
- 右上或列表上方：进入规划主动作

### Core Modules

1. 页面头部
2. 筛选栏
3. 待规划订单列表
4. 批量选择与进入规划动作区

### Required Fields

- 订单号
- 提货地
- 收货地
- 重量 / 体积
- 运输类型
- 时效要求
- 当前状态

### Recommended Tags

- `整车`
- `零担`
- `待规划`
- `规划中`
- `前程陆运说明`

### Key Interactions

- 支持按订单号、提货地、收货地、时效要求、运输方式筛选
- 支持单选进入规划
- 支持批量勾选后进入合并规划判断
- 若订单已被锁定或正在规划，状态需显著提示且不应误导为可立即处理

### Visual Priority

- 第一优先：列表状态和运输类型标签
- 第二优先：起讫地和时效要求
- 第三优先：重量体积等辅助判断字段

### Demo Focus

- 强调订单来自 ERP/WMS，同步后进入统一待规划入口
- 强调这里不是直接选承运商，而是先筛出需要进入规划判断的订单
- 强调 FTL/LTL 标签提前出现，为后续规划页做铺垫

### Empty and Exception States

- 空状态：`暂无待规划订单`
- 锁定态：需提示订单已被他人处理或占用
- 数据缺失态：允许进入规划页补齐，但不能直接形成推荐结果

### Main Action

- 主按钮：`进入规划`

## Page 2: 运输规划页

### Page Goal

- 让听众理解为什么订单需要先做规划判断，而不是直接选择承运商
- 把 FTL 主线和 LTL 对照关系在同页内讲清

### Demo Role

- 这是从订单筛选进入运输决策的核心页面
- 负责承接订单上下文，并产出后续推荐所依赖的方案判断

### Suggested Layout

- 左侧：订单摘要与关键约束信息
- 中部：规划判断区
- 右侧：推荐结果预览或推荐摘要

### Core Modules

1. 订单摘要区
2. 关键约束区
3. 规划判断区
4. FTL/LTL 对照区
5. 推荐摘要区

### Required Fields

- 订单基础信息摘要
- 起讫地
- 重量 / 体积
- 时效要求
- 运输类型初判
- 是否适合整车直发
- 是否适合零担补位
- 方案差异说明

### Key Interactions

- 查看订单是否适合整车直发
- 查看是否需要拆单或与其他订单合并
- 在多个候选方案间比较差异
- 进入推荐区查看候选承运商

### Visual Priority

- 第一优先：规划结论和判断依据
- 第二优先：FTL 主线与 LTL 对照关系
- 第三优先：订单摘要和约束信息

### Demo Focus

- 强调系统先做规划，再做推荐，不是直接平铺承运商列表
- 强调整车是主演示线，零担只作为同页补充对照
- 强调多方案时要展示差异，而不是只给黑盒结论

### Suggested Decision Notes

- `推荐整车直发：时效更稳，适合当前订单批次`
- `零担补位可作为备选，但在本次主场景中不作为默认主方案`
- `当前方案已满足主线路时效要求，可进入承运商推荐`

### Empty and Exception States

- 加载态：显示规划计算中
- 无方案态：提示重量超限、时效无法满足或无可用承运商
- 数据缺失态：保留在当前页并高亮缺失项

### Main Action

- 主按钮：`查看承运商推荐`

## Page 3: 承运商推荐 / 竞价结果区

### Page Goal

- 让听众理解推荐依据是可信的
- 让调度员能比较多个候选承运商，并理解系统默认推荐与人工切换排序的差异

### Demo Role

- 这是演示中最核心的说服页面
- 负责体现系统推荐能力，而不是只展示报价列表

### Suggested Layout

- 顶部：推荐区标题、当前排序规则、场景标签
- 中部：2 到 3 个核心候选承运商横向对比卡片或表格
- 辅助区：推荐原因、市场参考价、偏差提示、竞价结果补充分支
- 底部或右下：确认指派主动作

### Core Modules

1. 推荐区头部
2. 候选承运商对比区
3. 推荐原因说明区
4. 排序切换区
5. 异常或竞价补充分支区

### Required Fields

- 承运商名称
- 综合评分
- 当前报价
- 市场参考价
- 报价偏差
- 预计时效
- 运力可用性
- 准时率
- 异常率 / 破损率
- 履约成功率
- 推荐原因
- 适配场景标签

### Recommended Labels

- `系统推荐`
- `报价最低`
- `时效最优`
- `KPI 最优`
- `整车直发`
- `零担补位`
- `前程陆运说明`

### Key Interactions

- 默认按综合评分排序
- 支持切换为报价最低、时效最优、KPI 最优
- 支持在 2 到 3 个候选之间横向比较
- 若无协议承运商，可进入竞价/招标结果区，但不跳出主页面节奏

### Visual Priority

- 第一优先：系统推荐候选和推荐原因
- 第二优先：价格、时效、KPI 的横向差异
- 第三优先：市场参考价和报价偏差提示

### Demo Focus

- 先讲默认综合推荐，再讲排序切换后的差异
- 强调系统推荐是辅助决策，不是自动拍板
- 让听众看到推荐依据足够透明，支持人工复核

### Side Branch Placement

- 前程陆运说明建议放在场景标签或推荐原因中
- 建议示例：`前程陆运场景需先校验截关时间，当前候选已满足要求`
- 若候选无法满足截关，应显式降级，不得显示为默认优先推荐

### Empty and Exception States

- 推荐结果过期：阻断确认，提示刷新
- 无协议承运商：提示改走竞价或人工介入
- 竞价结果不满足时效：提示人工介入
- 排序切换后：保留当前排序规则提示，避免误解系统默认推荐

### Main Action

- 主按钮：`确认指派`

## Page 4: 确认指派与任务生成结果

### Page Goal

- 让听众确认本次闭环已经成立
- 给调度员一个清晰、低风险的收口动作和结果反馈

### Demo Role

- 这是从推荐选择进入正式运输任务的收口页面
- 负责体现最终确认和结果可见性

### Suggested Layout

- 上半区：确认指派摘要或二次确认弹层内容
- 下半区：任务生成结果卡片或结果面板
- 底部：后续动作入口

### Core Modules

1. 确认指派摘要区
2. 二次确认区
3. 提交反馈区
4. 任务生成结果区
5. 后续入口区

### Required Fields

- 订单数量
- 选中承运商
- 关键时效承诺
- 任务编号
- 当前状态
- 任务创建时间
- 下一步建议动作

### Key Interactions

- 点击确认指派后触发二次确认
- 二次确认通过后提交指派
- 成功后进入任务生成结果展示
- 提供返回订单池或查看运输任务入口

### Visual Priority

- 第一优先：确认对象是否正确，包括订单、承运商、时效承诺
- 第二优先：任务生成结果是否明确
- 第三优先：后续入口是否清晰

### Demo Focus

- 强调最终决定权仍在调度员
- 强调二次确认是为了降低误指派风险
- 强调到结果页时，本次 demo 闭环已经成立

### Suggested Result Copy

- 成功标题：`已生成国内陆运运输任务`
- 成功说明：`所选订单已完成承运商指派，可继续查看任务详情或返回订单池。`
- 部分成功说明：`本次批量指派部分完成，请查看失败原因后继续处理。`

### Empty and Exception States

- 提交中：按钮不可重复点击
- 推荐结果变化：阻断提交并要求刷新
- 权限不足：阻断提交并保留当前上下文
- 任务生成失败：说明失败数量与原因，不只给笼统失败提示

### Main Actions

- 主按钮：`确认并生成任务`
- 次按钮：`返回订单池`
- 次按钮：`查看运输任务`
