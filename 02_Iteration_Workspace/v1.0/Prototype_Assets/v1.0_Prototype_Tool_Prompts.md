# v1.0 Prototype Tool Prompts

## Purpose

本文件用于为 `Stitch`、`Gemini Canvas` 或其他专业原型生成工具提供可直接使用的提示词资料。

使用建议：

- 先用 `Global Prompt` 设定整体风格和场景
- 再按页面使用对应 `Page Prompt`
- 若工具支持补充上下文，可同时附上 `Page Spec` 和 `Screen Content` 中的相关片段

## Global Prompt

```text
Create a professional B2B prototype for a shipper-side transportation management dashboard. The scenario is domestic factory-to-factory trucking in China. The main user is a shipper dispatcher. The main workflow is: order pool -> transportation planning -> carrier recommendation -> confirm assignment -> transport task created.

Style requirements:
- enterprise dashboard
- logistics control tower
- clean, structured, high information density
- desktop-first web application
- neutral and professional visual tone
- use tables, cards, tabs, tags, and clear primary buttons

Business constraints:
- FTL is the main storyline
- LTL is only a comparison block on the planning page
- export first-leg trucking is only a side note, not a separate flow
- if an order is export first-leg, carrier recommendation must check cutoff time before price-based preference
- do not design driver execution, tracking, proof of delivery, or freight settlement pages
```

## Tool Input Tips

- 若工具偏英文理解更强，优先使用英文 prompt，但页面文案保留中文
- 若工具支持上传参考文本，可附上：
  - `v1.0_Page_Spec.md`
  - `v1.0_Screen_Content.md`
- 若工具支持逐屏生成，建议按页面 1 到页面 4 依次生成，不要一次生成整套复杂流程

## Page 1 Prompt

```text
Design a desktop web page for a shipper logistics dashboard called "订单池 / 待规划列表".

Layout:
- top navigation bar
- page header with title and subtitle
- one-row filter bar with search, transport type, SLA, order status, customer, pickup date
- bulk action row above a wide data table
- primary button on the upper right labeled "进入规划"

Content:
- a wide table showing order number, source, pickup location, delivery location, weight/volume, transport type, required arrival time, scenario tag, current status, and action
- use tags like 整车, 零担, 待规划, 规划中, 前程陆运说明
- add a small status hint: 今日已同步 28 条订单，其中 9 条待规划

Design direction:
- enterprise operations dashboard
- efficient and data-first
- not a consumer marketplace app
```

## Page 2 Prompt

```text
Design a desktop transportation planning page for a shipper control tower called "运输规划".

Layout:
- top navigation and breadcrumb
- three-column layout
- left column for order summary and constraints
- center column for planning conclusion and FTL vs LTL comparison
- right column for recommendation preview and next step
- primary button at the bottom right labeled "查看承运商推荐"

Content:
- emphasize a main conclusion tag: 推荐整车直发
- show order summary fields such as order ID, pickup, delivery, weight, volume, SLA
- show a comparison block between FTL and LTL
- right side should preview that 3 carrier recommendations are available

Design direction:
- analytical operations page
- structured B2B dashboard
- clear hierarchy from order context to planning decision
```

## Page 3 Prompt

```text
Design a desktop carrier recommendation page for a domestic logistics management dashboard called "承运商推荐".

Layout:
- page header with current sorting rule and scenario tag
- sorting tabs: 综合评分优先, 报价最低, 时效最优, KPI 最优
- main comparison area with three carrier cards side by side
- lower support area with recommendation notes, market benchmark notes, export first-leg rule note, and bidding branch
- primary action button labeled "确认指派"

Content for each carrier card:
- carrier name
- score
- current price
- market benchmark price
- price deviation
- transit time
- on-time rate
- exception rate
- fulfillment rate
- capacity status
- recommendation reason
- scenario tags

Business note:
- include a subtle rule note that for export first-leg orders, cutoff time must be checked before default recommendation priority
- show that a lower-price carrier can be downgraded if cutoff time is not met

Design direction:
- trustworthy decision-support interface
- transparent recommendation logic
- high information density but still readable
```

## Page 4 Prompt

```text
Design a desktop confirmation and result page for a shipper transportation dashboard.

Layout:
- confirmation summary area or modal at the top
- result panel below
- action buttons at the bottom

Content:
- confirmation title: 确认指派承运商
- summary fields: order count, selected carrier, transit SLA, current quote, recommendation basis
- success result panel with task ID, carrier name, current status, created time, next-step suggestion
- primary action after success: 查看运输任务
- secondary action: 返回订单池

Design direction:
- operational, stable, low-risk
- make the user feel the workflow has been completed successfully
- avoid flashy celebration design
```

## Compact One-Shot Prompt

```text
Design 4 connected desktop web prototype screens for a shipper-side transportation management demo in China. The workflow is order pool, transportation planning, carrier recommendation, and assignment result. The main story is domestic factory-to-factory FTL trucking. LTL only appears as a comparison section in the planning page. Export first-leg trucking only appears as a rule note in the recommendation page, where cutoff time must be checked before default recommendation. The UI style should be a professional enterprise logistics control tower with tables, cards, tags, tabs, and clear action buttons. Avoid consumer app aesthetics and avoid execution or settlement pages.
```

## Chinese Prompt Version

### 通用中文提示词

```text
请生成一套面向货主侧调度员的桌面端物流运输管理原型，场景为中国国内工厂到工厂陆运。主流程为：订单池 -> 运输规划 -> 承运商推荐 -> 确认指派 -> 运输任务生成结果。整体风格为企业级控制塔工作台，信息密度高、结构清晰、偏 B2B 运营后台，不要做成消费端产品。

约束条件：
- 整车 FTL 是主演示线
- 零担 LTL 只在规划页作为同页对照
- 前程陆运只作为推荐页中的规则说明，不单独做页面
- 若订单属于前程陆运场景，推荐时必须先校验截关时间，再决定默认推荐优先级
- 不需要司机执行、在途跟踪、签收回单、费率对账页面
```

## Handoff Notes

- 若工具首轮生成偏空泛，可把本文件的单页 prompt 与 `v1.0_Screen_Content.md` 中的字段示例一起贴入
- 若工具生成风格太像消费端，可补充强调：`enterprise dashboard`, `B2B operations`, `logistics control tower`
- 若工具把前程陆运画成独立页面，应在下一轮 prompt 中明确：`export first-leg is a side note only, not a separate screen`
