# v1.0 Gemini Canvas Review Fix Prompts

## Purpose

本文件用于承接对 `Gemini Canvas` 生成结果的 review 后修正。

适用场景：

- 页面已经生成出来
- 需要根据评审意见做一轮或多轮定向修正
- 重点用于修正主线偏移、数据不一致、规则表达错误、页面气质偏差等问题

## Recommended Use Order

1. 先使用 `Round 1` 收主线
2. 再使用 `Round 2` 修数据一致性与选择逻辑
3. 最后使用 `Round 3` 专修承运商推荐页可信度
4. 若你只想快速试一轮，可直接使用文末的 `Compact Fix Prompt`

## Round 1: Re-Center The Main Storyline

### English

```text
Refine the existing prototype to align more strictly with the approved demo scope.

Important scope rules:
- The main scenario is domestic factory-to-factory trucking for shipper-side dispatchers.
- Export first-leg trucking is only a supporting side note, not the main storyline.
- Do not let port, customs, EDI, or export-first-leg elements dominate the interface.
- Reduce the visual weight of Yangshan port, customs sync, EDI references, and export-first-leg indicators across the screens.
- Keep export first-leg only as a subtle rule note or scenario explanation, mainly on the carrier recommendation screen.
- The overall prototype should feel like a domestic trucking control tower for shippers, not an export logistics control center.

Please rebalance the prototype so that the main value shown is:
order pool -> transportation planning -> carrier recommendation -> confirm assignment -> task result
for domestic factory-to-factory transportation.
```

```text
请把当前原型进一步收口到已经确认的 demo 范围。

范围规则：
- 主场景是货主侧调度员的国内工厂到工厂陆运。
- 前程陆运只是辅助性支线，不是主演示线。
- 不要让港口、海关、EDI、前程陆运元素成为页面主角。
- 请降低洋山港、海关同步、EDI、前程陆运相关元素在页面中的视觉权重。

这条国内工厂到工厂运输主线。
```

## Round 2: Fix Selection And Data Consistency

### English

```text
Refine the interaction logic and data consistency of the prototype.

Fix these issues:
- The transportation planning screen must reflect the actually selected order or selected orders from the order pool.
- Do not keep the planning page hardcoded to one fixed order if the user selected a different one.
- Locked orders with status 规划中 must not be included in bulk select or full select behavior.
- Selection logic should consistently prevent locked orders from entering the planning flow.
- The planning summary, route, SLA, and recommendation preview should update based on the current selection context.

The prototype should feel internally consistent:
what the user selects in screen 1 should be what the user sees in screen 2 and later screens.
```

### 中文对照

```text
请修正原型中的交互逻辑和数据一致性问题。

需要修正：
- 运输规划页必须反映订单池中当前实际选择的订单或订单集合。
- 如果用户选了不同订单，规划页不能始终写死为同一个固定订单。
- 状态为“规划中”的锁定订单，不能被批量全选或全量选中逻辑带入。
- 选择逻辑应始终阻止锁定订单进入规划流程。
- 规划摘要、线路、时效和推荐摘要应根据当前选择上下文动态变化。

原型需要体现出内部一致性：
用户在第一页选了什么，第二页及后续页面就应该展示什么。
```

## Round 3: Fix Recommendation Credibility

### English

```text
Refine the carrier recommendation screen to improve business credibility.

Please fix these recommendation-page issues:
- Keep the page as a transparent decision-support screen for shipper dispatchers.
- Ensure all downgrade logic and business copy are internally consistent.
- If a carrier is downgraded because cutoff time is not satisfied, the downgrade text must refer to the correct carrier.
- Do not state that a carrier has a lower quote if the displayed quote is actually higher.
- Make the comparison between candidates easier to trust at a glance:
  score, price, market benchmark, deviation, transit time, KPI metrics, capacity status, recommendation reason, and scenario tags should all be clearly aligned.
- The export first-leg rule note should remain visible but secondary.
- Do not make the export-first-leg toggle feel like the primary control of the page.
- Prefer making the rule note a supporting explanation rather than a dominant interaction element.

The final impression should be:
the recommendation is evidence-based, internally consistent, and easy to audit.
```

### 中文对照

```text
请优化承运商推荐页，提升业务可信度。

需要修正：
- 保持这一页是面向货主调度员的透明决策支持页。
- 确保所有降级逻辑和业务文案前后一致。
- 如果某个承运商因为不满足截关时间而被降级，降级文案必须准确对应那个承运商。
- 如果页面展示的报价更高，就不要写成“报价更低”。
- 让候选对比更容易被一眼信任：
  评分、报价、市场参考价、偏差、时效、KPI、运力状态、推荐原因、场景标签都要清晰对齐。
- 前程陆运规则说明应保持可见，但仍然是次级信息。
- 不要让前程陆运开关看起来像这个页面的主控制项。
- 更适合把该规则做成辅助说明，而不是主交互焦点。

最终要让人感觉：
推荐是有证据的、前后一致的、可审计的。
```
