# v1.0 Gemini Canvas Final Workflow

## Purpose

本文件用于沉淀 `v1.0` 当前已经验证有效的 `Gemini Canvas` 原型生成流程。

目标：

- 减少后续往返次数
- 明确先生成什么、后修什么
- 明确什么时候应该停止继续微调

## Final Recommended Workflow

### Step 1: Lock Guardrails First

- 先确认主场景、支线边界、不可平级展示规则、页面语言风格、停止条件
- 不先写长 prompt

### Step 2: Generate 1-2-3 Mainline First

- 先生成页面 1：订单池
- 再生成页面 2：运输规划
- 再生成页面 3：承运商推荐
- 页面 4 最后补

原因：

- 页面 3 是最容易跑偏的核心页
- 页面 3 稳住之后，再补页面 4 更高效

### Step 3: Use Ready-To-Paste Files

- 页面 1：`v1.0_Gemini_Canvas_Screen1_Ready_To_Paste.md`
- 页面 2：`v1.0_Gemini_Canvas_Screen2_Ready_To_Paste.md`
- 页面 3：`v1.0_Gemini_Canvas_Screen3_Ready_To_Paste.md`
- 页面 4：`v1.0_Gemini_Canvas_Screen4_Ready_To_Paste.md`

### Step 4: Review In Small Rounds

- 每轮最多只修 2 个问题
- 优先修：主线偏移、数据不一致、推荐页可信度
- 不要一轮中同时修 5 到 8 个问题

### Step 5: Use Review Fix Prompts In Stages

- Stage 1：修主线、修动态一致性、修推荐可信度
- Stage 2：压支线、压系统感
- Stage 3：最后轻修

对应文件：

- `v1.0_Gemini_Canvas_Review_Fix_Prompts.md`

### Step 6: Stop At Review-Ready

达到以下条件时停止继续微调：

- 主场景不再跑偏
- 页面 3 推荐可信度成立
- 页面 4 结果页不再扩成执行系统页
- 剩余问题只属于轻量措辞优化

## Final Status Of v1.0

- 当前 `Gemini_Canvas/tms_control_tower.tsx` 已可作为 `v1.0` 原型评审基线
- 后续若继续优化，优先做局部轻修，不建议再大改主线结构
