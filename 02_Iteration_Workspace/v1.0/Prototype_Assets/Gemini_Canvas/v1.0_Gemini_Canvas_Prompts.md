# v1.0 Gemini Canvas Prompts

## Purpose

本文件用于给 `Gemini Canvas` 提供更结构化、更适合分模块描述的原型提示词。

语言说明：

- 主 brief 以英文为主，便于提升生成稳定性
- 本文件保留中文章节标题、中文版本和中文使用说明，作为中英文对照的一部分

使用建议：

- 先贴 `Canvas Global Setup`
- 再逐页贴 `Canvas Screen Brief`
- 如果工具支持长上下文，可一起附上 `v1.0_Page_Spec.md` 和 `v1.0_Screen_Content.md`

## Gemini Canvas Prompt Style

- 使用明确的场景、用户、目标、布局、内容模块
- 强调模块层级和信息关系
- 允许比 Stitch 略长，但仍要避免过度啰嗦

## Canvas Global Setup

```text
Create a desktop prototype for a shipper-side transportation management control tower in China.

User:
- shipper dispatcher

Business scenario:
- domestic factory-to-factory trucking

Workflow:
- order pool
- transportation planning
- carrier recommendation
- confirm assignment
- transport task result

Product constraints:
- FTL is the main storyline
- LTL appears only as a comparison section on the planning page
- export first-leg trucking is only a supporting rule note on the recommendation page
- for export first-leg orders, cutoff time must be checked before default recommendation priority
- do not create driver execution, tracking, POD, or settlement screens

Design direction:
- enterprise dashboard
- logistics control tower
- desktop-first
- high information density
- clean B2B interface
- clear hierarchy using tables, cards, tabs, tags, and action buttons
```

中文对照：

```text
请生成一套中国货主侧运输管理控制塔的桌面端原型。

用户：
- 货主调度员

业务场景：
- 国内工厂到工厂陆运

主流程：
- 订单池
- 运输规划
- 承运商推荐
- 确认指派
- 运输任务结果

产品约束：
- 整车 FTL 是主演示线
- 零担 LTL 只在规划页中作为对照区块
- 前程陆运只作为推荐页中的辅助规则说明
- 若订单属于前程陆运场景，推荐时必须先校验截关时间，再决定默认推荐优先级
- 不要生成司机执行、在途跟踪、回单签收或费率结算页面

设计方向：
- 企业级后台
- 物流控制塔
- 桌面端优先
- 高信息密度
- 干净的 B2B 界面
- 用表格、卡片、标签、页签和动作按钮建立清晰层级
```

## Canvas Correction Prompts

### If the layout becomes too decorative

```text
Reduce decoration and make the design more enterprise-like. Increase structure, improve hierarchy, and emphasize tables, cards, and operational clarity over visual flourish.
```

中文对照：

```text
请减少装饰性设计，让界面更像企业级后台。增强结构感和层级感，优先突出表格、卡片和运营清晰度，而不是视觉花哨感。
```

### If the recommendation page is too simplistic

```text
Increase the information density of the carrier recommendation screen. Show more comparison detail across price, timing, KPI, market benchmark, and recommendation reasoning while keeping the page readable.
```

中文对照：

```text
请提高承运商推荐页的信息密度。增加价格、时效、KPI、市场参考价和推荐原因等比较细节，同时保持页面可读性。
```

### If the tool adds extra screens

```text
Keep the prototype to four core desktop screens only. Do not add extra execution, tracking, settlement, or separate export first-leg screens.
```

中文对照：

```text
请把原型控制在 4 个核心桌面页面内，不要增加执行端、跟踪、结算或独立的前程陆运页面。
```
