# v1.0 Stitch Prompts

## Purpose

本文件用于给 `Stitch` 提供更短、更聚焦页面生成的提示词。

语言说明：

- 主 prompt 以英文为主，便于提升生成稳定性
- 本文件保留中文章节标题与使用说明，作为中英文对照的一部分

使用建议：

- 先贴 `Global Prompt`
- 再逐页贴对应 `Screen Prompt`
- 若首轮生成过于空泛，再补贴 `v1.0_Screen_Content.md` 中的字段示例

## Stitch Prompt Style

- 尽量短句
- 尽量直接描述页面目标和模块
- 不堆太多背景解释
- 先生成 1 页，再继续下一页

## Global Prompt

```text
Create a desktop enterprise logistics dashboard prototype for a shipper dispatcher in China. Main workflow: order pool -> transportation planning -> carrier recommendation -> confirm assignment -> task result. Main scenario: domestic factory-to-factory trucking. FTL is the main flow. LTL is only a comparison section. Export first-leg is only a side note, not a separate screen. Use a clean B2B control tower style with tables, cards, tabs, tags, and clear primary buttons.
```

中文对照：

```text
请生成一套桌面端企业级物流控制塔原型，面向中国货主调度员。主流程为：订单池 -> 运输规划 -> 承运商推荐 -> 确认指派 -> 任务结果。主场景是国内工厂到工厂陆运。整车 FTL 是主流程，零担 LTL 只作为对照区块。前程陆运只作为说明性支线，不单独形成页面。整体风格采用干净、专业的 B2B 控制塔界面，使用表格、卡片、标签、页签和明确的主按钮。
```

## Screen 1 Prompt

```text
Design a desktop page called 订单池 / 待规划列表 for a shipper logistics dashboard. Add a top bar, page title, subtitle, one-row filter area, bulk action row, and a wide data table. The main action button is 进入规划. Show columns for order number, source, pickup, delivery, weight/volume, transport type, required arrival time, scenario tag, current status, and action. Use tags like 整车, 零担, 待规划, 规划中, 前程陆运说明. The page should feel like a professional B2B operations dashboard.
```

中文对照：

```text
请设计一个桌面端页面，名称为“订单池 / 待规划列表”，用于货主侧物流工作台。页面包含顶栏、页面标题、副标题、单行筛选区、批量操作条和宽表格。主按钮为“进入规划”。表格需展示订单号、来源、提货地、收货地、重量/体积、运输类型、时效要求、场景标签、当前状态和操作。使用“整车、零担、待规划、规划中、前程陆运说明”等标签。整体风格应像专业的 B2B 运营控制台。
```

## Screen 2 Prompt

```text
Design a desktop page called 运输规划. Use a three-column layout. Left column shows order summary and key constraints. Center column shows planning conclusion and an FTL vs LTL comparison block. Right column shows recommendation preview and next-step hint. Make 推荐整车直发 the main conclusion. The primary button is 查看承运商推荐. The design should be structured, analytical, and enterprise-focused.
```

中文对照：

```text
请设计一个桌面端页面，名称为“运输规划”。页面采用三栏布局：左侧展示订单摘要和关键约束，中间展示规划结论与 FTL/LTL 对照区，右侧展示推荐摘要和下一步提示。让“推荐整车直发”成为页面主结论。主按钮为“查看承运商推荐”。整体设计应结构清晰、偏分析型、偏企业级后台。
```

## Screen 3 Prompt

```text
Design a desktop page called 承运商推荐 for a domestic logistics control tower. Add sorting tabs: 综合评分优先, 报价最低, 时效最优, KPI 最优. Show 3 carrier comparison cards side by side. Each card should show carrier name, score, current price, market benchmark, price deviation, transit time, KPI metrics, capacity status, recommendation reason, and scenario tags. Add a subtle rule note: if the order is export first-leg, cutoff time must be checked before default recommendation priority. The primary action is 确认指派.
```

中文对照：

```text
请设计一个桌面端页面，名称为“承运商推荐”，用于国内物流控制塔。页面加入排序页签：综合评分优先、报价最低、时效最优、KPI 最优。横向展示 3 张承运商对比卡片。每张卡片展示承运商名称、评分、当前报价、市场参考价、报价偏差、运输时效、KPI 指标、运力状态、推荐原因和场景标签。页面中加入一条轻量规则说明：如果订单属于前程陆运场景，必须先校验截关时间，再决定默认推荐优先级。主按钮为“确认指派”。
```

## Screen 4 Prompt

```text
Design a desktop confirmation and result page for carrier assignment. Show a confirmation summary at the top with order count, selected carrier, SLA, current quote, and recommendation basis. Below it show a success result panel with task ID, carrier name, current status, created time, and next-step suggestion. Primary action after success is 查看运输任务. Secondary action is 返回订单池. Keep the page professional, stable, and low-risk.
```

中文对照：

```text
请设计一个桌面端的承运商确认与结果页面。页面顶部展示确认摘要，包括订单数量、选中承运商、时效承诺、当前报价和推荐依据。下方展示成功结果面板，包括任务编号、承运商名称、当前状态、创建时间和下一步建议。成功后的主按钮为“查看运输任务”，次按钮为“返回订单池”。整体风格保持专业、稳定、低风险。
```

## One-Shot Prompt

```text
Design 4 connected desktop web prototype screens for a shipper-side transportation management demo. The flow is order pool, transportation planning, carrier recommendation, and assignment result. The main story is domestic factory-to-factory FTL trucking. LTL only appears as a comparison section. Export first-leg appears only as a rule note in the recommendation page. Use a professional B2B logistics control tower style. Avoid consumer app aesthetics.
```

中文对照：

```text
请设计 4 个相互衔接的桌面端原型页面，用于货主侧运输管理 demo。流程包括订单池、运输规划、承运商推荐和指派结果。主线为国内工厂到工厂整车运输。零担只作为对照区块出现。前程陆运只作为推荐页中的规则说明出现。整体采用专业的 B2B 物流控制塔风格，避免消费端产品视觉。
```

## Recovery Prompts

### If the tool makes it too consumer-facing

```text
Make the UI more like an enterprise operations dashboard and less like a consumer app. Increase information density, use cleaner tables and cards, reduce decorative elements, and keep the tone professional and operational.
```

中文对照：

```text
请把界面调整得更像企业运营后台，而不是消费端应用。提高信息密度，使用更干净的表格和卡片，减少装饰性元素，保持专业、运营型的视觉语气。
```

### If the tool expands export first-leg into a separate page

```text
Do not create a separate export first-leg screen. Keep export first-leg only as a small rule note or scenario tag inside the carrier recommendation page.
```

中文对照：

```text
不要把前程陆运做成独立页面。请仅在承运商推荐页中以小型规则说明或场景标签的方式体现前程陆运。
```

### If the tool makes the planning page too weak

```text
Strengthen the transportation planning page. Make the planning conclusion the visual focus, with a clear FTL vs LTL comparison and a visible next action to carrier recommendation.
```

中文对照：

```text
请增强运输规划页的表现。让规划结论成为视觉重点，加入清晰的 FTL 与 LTL 对照，并让进入承运商推荐的下一步动作足够明显。
```

## Handoff Notes

- Stitch 更适合逐页生成，不建议一开始就要求完整高复杂度全流程
- 若某页结构跑偏，优先用 Recovery Prompt 修正，不要立即重写全部 prompt
- 若后续补充新的中文 prompt 版本，建议与对应英文 prompt 放在同一文件中逐段对照维护
