# v1.0 Wireframe Notes

## Purpose

本文件不直接产出原型图，而是为 `Stitch`、`Gemini Canvas` 或人工线框绘制提供结构化落图说明。

使用方式：

- 可直接作为线框图绘制说明
- 可作为专业原型工具的布局参考资料
- 可与 `v1.0_Page_Spec.md` 和 `v1.0_Screen_Content.md` 组合使用

## Global Wireframe Rules

- 页面风格应偏企业级控制塔工作台，不做营销页或消费端风格
- 布局以清晰、稳重、信息分层明确为优先
- 主色只需轻度强调，避免过多装饰性视觉元素
- 每页必须有明确主动作按钮，且位置稳定
- 主信息区优先展示决策相关内容，次要说明放在侧边或下方
- 前程陆运只作为说明性支线，通过标签、提示条或说明区体现
- 页面文案与视觉表达应偏业务决策说明，避免过度强调“大平台”“大优化”“大执行中心”等系统化叙事

## Visual Style Guidance For Tools

- 风格关键词：`enterprise dashboard` `logistics control tower` `clean B2B interface` `professional operations UI`
- 版式关键词：`12-column layout` `clear hierarchy` `data-first layout` `card plus table composition`
- 避免关键词：`consumer app` `playful` `colorful marketing landing page` `mobile shopping app`

## Shared Layout Elements

### Top Navigation

- 建议保留轻量顶栏
- 左侧：产品名或模块名，例如 `TMS Shipper`
- 中部或左下：面包屑
- 右侧：用户、通知、帮助入口

### Page Header

- 每页需有标题和一句副标题
- 标题下方可放状态提示或场景说明

### Main Action Placement

- 若页面以列表为主，主动作放右上角或列表上方右侧
- 若页面以流程推进为主，主动作放右下角或内容区底部右侧

### Status Presentation

- 空态：居中空状态卡片
- 异常态：页面内警示条或局部错误提示
- 成功态：结果卡片或成功面板
- 加载态：骨架屏或区块级 loading，不建议整页纯转圈

## Page 1 Wireframe: 订单池 / 待规划列表

### Layout Intention

- 这是典型数据入口页
- 重心应放在“筛选 + 列表 + 进入规划”三段结构

### Suggested Structure

1. 顶栏
2. 页面标题区
3. 筛选区
4. 批量操作条
5. 订单列表区

### Layout Description

- 顶部放页面标题 `订单池 / 待规划列表` 和副标题
- 标题下方放一条轻提示：`今日已同步 28 条订单，其中 9 条待规划`
- 再下方放一整行筛选区，建议使用 5 到 6 个筛选控件横向排布
- 列表上方左侧显示已选条数，右侧放主按钮 `进入规划`
- 主内容为宽表格，适合展示多列字段

### Component Guidance

- 筛选区使用：搜索框、下拉框、日期选择、快捷筛选 chip
- 列表使用：带复选框的数据表格
- 状态和场景建议用标签组件，不要只用纯文本
- `进入规划` 按钮要明显，建议主色按钮

### Information Hierarchy

- 第一层：订单号、起讫地、运输类型、当前状态
- 第二层：重量 / 体积、时效要求
- 第三层：场景标签、来源系统

### Special Placement

- `前程陆运说明` 标签只在少量订单行出现，避免大面积抢占注意力
- `规划中` 状态建议使用醒目但不刺眼的强调色

### Tool Prompt Snippet

`Design an enterprise logistics order pool page with a wide data table, top filter bar, bulk action row, and a clear primary action button labeled 进入规划. The page should look like a B2B operations dashboard for shippers, not a consumer app.`

## Page 2 Wireframe: 运输规划页

### Layout Intention

- 这是分析判断页，不是纯列表页
- 应该让用户一眼看出“左边是订单上下文，中间是规划结论，右边是推荐摘要”

### Suggested Structure

1. 顶栏
2. 页面标题区
3. 三栏主布局
4. 底部动作区

### Layout Description

- 页面主体建议使用三栏布局
- 左栏宽度约 25%，放订单摘要和关键约束
- 中栏宽度约 45%，放规划判断结果和 FTL/LTL 对照区
- 右栏宽度约 30%，放推荐摘要和下一步动作提示
- 页面底部右侧放主按钮 `查看承运商推荐`

### Component Guidance

- 左栏使用 2 个纵向堆叠卡片：`订单摘要` `关键约束`
- 中栏上半区放结论卡片，下半区放 FTL/LTL 对照表
- 右栏放推荐摘要卡片和状态提示条
- 若需要 loading，优先在中栏规划判断区显示骨架内容

### Information Hierarchy

- 第一层：`推荐整车直发` 这类结论标签和主说明
- 第二层：整车与零担方案差异对照
- 第三层：订单基础字段和补充约束

### Special Placement

- 让 `推荐整车直发` 成为中栏最显眼元素
- `零担作为备选` 不要做成同等主视觉，应弱一级
- 不要在本页过早展开大量承运商信息，只放推荐摘要预告

### Tool Prompt Snippet

`Design a three-column transportation planning page for a shipper control tower. Left column shows order summary and constraints, center shows planning conclusion with FTL vs LTL comparison, right column shows recommendation preview and next action. Use a clean enterprise dashboard style.`

## Page 3 Wireframe: 承运商推荐 / 竞价结果区

### Layout Intention

- 这是核心说服页
- 页面重点是“推荐依据透明”和“候选横向对比”

### Suggested Structure

1. 顶栏
2. 页面标题区
3. 排序切换区
4. 承运商对比主区
5. 辅助说明区
6. 底部动作区

### Layout Description

- 标题区下方先放当前排序规则和场景标签
- 排序切换建议用 tab 或 segmented control
- 主体建议用 3 张横向对比卡片，或者 1 张对比表加卡片摘要
- 辅助说明区放在主对比区下方，包含推荐原因说明、市场参考价提示、前程陆运规则说明、竞价分支
- 右下角或底部固定主按钮 `确认指派`

### Component Guidance

- 候选承运商建议用高信息密度卡片
- `系统推荐` 标记要清晰，但不宜过度夸张
- 市场参考价和报价偏差建议放成次级指标行
- 前程陆运规则建议用浅色说明条或规则卡片
- 竞价结果区可折叠或作为下方附加分支模块

### Information Hierarchy

- 第一层：系统推荐承运商、综合评分、价格、时效
- 第二层：KPI 指标和推荐原因
- 第三层：市场参考价、偏差、场景标签、补充分支

### Special Placement

- `前程陆运规则说明` 建议放在推荐区下方偏右，或场景标签附近
- 降级示例要可见，但不要喧宾夺主
- 排序切换后，顶部必须仍保留“当前排序规则”说明

### Tool Prompt Snippet

`Design a carrier recommendation page for a domestic logistics control tower. Show three carrier comparison cards side by side with score, price, market benchmark, time, KPI metrics, capacity, and recommendation reasons. Include sorting tabs and a subtle rule note for export first-leg orders where cutoff time must be checked before price.`

## Page 4 Wireframe: 确认指派与任务生成结果

### Layout Intention

- 这是闭环收口页
- 页面要让用户感到“已确认、已生成、可继续下一步”

### Suggested Structure

1. 页面标题区
2. 二次确认弹层或确认摘要卡
3. 结果反馈区
4. 后续动作区

### Layout Description

- 如果做成两步演示，可先展示确认弹层，再切到结果面板
- 如果做成单页演示，可上半区是确认摘要，下半区是任务结果
- 结果区建议用成功卡片，视觉上明显区别于前几页的数据分析区
- 底部保留两个后续动作：`查看运输任务` 和 `返回订单池`

### Component Guidance

- 二次确认适合用 modal 或高强调摘要卡
- 结果面板适合用大卡片，包含任务编号、状态、承运商和下一步建议
- 若有部分成功场景，可在成功卡片下方追加一块异常摘要卡

### Information Hierarchy

- 第一层：确认对象是否正确，任务是否生成成功
- 第二层：任务编号、承运商、当前状态
- 第三层：下一步建议动作和异常补充

### Special Placement

- `确认并生成任务` 按钮应只在确认态出现一次，避免重复主按钮
- 成功后的主按钮切换为 `查看运输任务`
- 不要把结果页做成空洞 toast，必须保留结构化结果信息

### Tool Prompt Snippet

`Design a confirmation and result page for assigning a carrier in a B2B logistics dashboard. Show a confirmation summary with order count, carrier, SLA and price, then a success result panel with task ID, assigned status, created time, and next actions. Keep it clean, operational, and trustworthy.`

## Cross-Page Consistency Notes

- 页面标题位置保持一致
- 主按钮风格和位置逻辑保持一致
- 标签体系在四页中统一
- 表格、卡片、提示条风格统一
- 不要在某一页突然切换成过于花哨的设计语言
