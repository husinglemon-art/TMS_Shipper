# B端 PRD 深度检查规则

## 1. Purpose

本文件用于在需要做**完整审查**时，提供一套较全面的 B 端 PRD 检查规则。

说明：

- 日常版本检查、demo 收口，优先使用 `Quick_Check_Rule.md`
- 只有在需要做正式封版、完整质量回顾或复杂系统级评审时，再使用本文件

## 2. When To Use

适用场景：

- 正式封版前的完整审查
- 系统级或平台级规划评审
- 需要跨多个维度做全面质量回顾
- 需要新人理解完整检查框架

## 3. Review Sequence

完整检查建议按以下顺序进行：

1. 先做产品定型
2. 再判断哪些维度适用
3. 再逐维度检查
4. 最后输出 `veto` 和 `guide`

## 4. Product Typing First

在开始之前，先判断两个维度：

### 4.1 商业属性

- 自研内部系统
- 商业化产品

### 4.2 功能类型

- 业务型管理软件
- 工具型软件
- 交易型平台
- 基础服务型产品

## 5. Full Review Dimensions

深度检查时使用以下 14 个维度：

1. 业务分析质量
2. 产品类型适配性
3. 产品定位合理性
4. 场景分析与用户旅程
5. 文档结构完整性
6. 架构设计质量
7. 数据建模质量
8. 流程与角色设计
9. 交互设计质量
10. 商业分析深度
11. MVP 策略与演进蓝图
12. 异常处理与健壮性设计
13. AI 功能设计质量
14. 运营方案与效果跟踪

详细内容见：

- `Check_Dimensions/`

## 6. Output Rule

输出时只保留两类结果：

### Veto

必须拦截的问题，例如：

- 产品定位缺失
- 主流程断裂
- 角色权限完全缺失
- 关键异常完全没写

### Guide

需要优化的问题，例如：

- 结构不够清楚
- 交互说明不够细
- 商业分析不够深入
- 运营方案可再补强

## 7. How To Record Findings

每个维度检查时，优先记录：

- 问题是什么
- 对应文档位置在哪里
- 为什么会影响推进
- 建议怎么补

不要为了“凑数量”而输出无价值问题。

## 8. Output Location

输出文件：

- `check-prd-appendix-veto.md`
- `check-prd-appendix-guide.md`

默认放在：

- `02_Iteration_Workspace/v[当前版本号]/Audit_Reports/`

## 9. Practical Guideline

建议：

- 先快速判断是否需要完整 14 维
- 如果只是版本收口，不要直接上重审
- 如果是复杂规划，再逐维度展开
