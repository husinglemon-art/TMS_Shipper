# Agent Skills README

## 1. Purpose

本目录存放 `TMS_Shipper` 模板工程当前保留的核心 skill。

这些 skill 的用途不是堆数量，而是服务当前 PM 仓库的最小闭环：

- 需求访谈
- 竞品研究
- PRD 初稿
- 原型说明
- 终稿审计
- 主档治理

## 2. Current Rule

当前 skill 库采用以下管理原则：

1. 先保留最小核心集合
2. 不保留娱乐化、灵感噪音型 skill
3. 不保留重复能力的多个模板
4. 后续如果要补充，优先补业务真正高频使用的能力

## 3. Naming Rule

当前 skill 文件采用：

- 无编号
- 语义化命名
- 英文单词使用下划线连接

示例：

- `Diagram_Standard.md`
- `Problem_Definition.md`
- `Version_Map.md`
- `PRD_Review.md`

说明：
不再使用 `01_`、`02_` 这类流水号命名。

## 4. Grouping Rule

当前 skill 按职责分组管理，而不是按历史编号管理。

分组说明见：

- `Skill_Groups.md`

当前主要分组：

1. 核心文档与表达
2. 研究与需求分析
3. 原型与交互表达
4. 主档治理与审计

## 5. Add Rule

如果后续要新增 skill，先问 3 个问题：

1. 这个能力是否已经被现有 skill 覆盖？
2. 这个能力是否会在未来版本中高频使用？
3. 这个能力是否服务当前 PM 模板工程主流程？

只有当答案足够明确时，才新增文件。

建议新增的 skill 优先属于以下几类：

- 高频 PRD 结构模板
- 高频 demo 演示模板
- 高频评审检查模板
- 高频原型说明模板

## 6. Remove Rule

满足以下任意条件的 skill，应优先考虑删除：

- 没有任何角色或流程引用
- 与当前主流程弱相关
- 只是灵感发散，不形成稳定产出
- 与其他 skill 明显重复

## 7. Replacement Rule

如果后续要替换现有 skill，建议按这个顺序进行：

1. 先替换“研究与需求分析”组
2. 再替换“原型与交互表达”组
3. 最后替换“主档治理与审计”组

原因：

- 前两组更依赖你的真实业务方式
- 最后一组更偏仓库底座，替换成本更高

## 8. Current Status

当前 skill 库已完成一轮精简与首轮替换。

- 当前核心 skill 数量：`16`
- 当前管理方式：职责分组 + 语义化命名
- 当前目标：先试跑，再按需补充
