# Artifact Context Intake

## 1. Purpose

本 skill 用于帮助 **B 端供应链系统产品经理** 先读材料、再问问题、最后整理结论。

它的目标不是泛泛做“上下文吸收”，而是解决你们日常最常见的问题：

- 访谈纪要很多，但没人先帮你捋清重点
- 业务材料很散，不知道哪些信息值得进入 PRD
- demo 输入很多，但不知道先抓哪条主线
- 用户已经给了材料，却还在反复被追问

## 2. Default Context

默认适用于以下输入材料：

- 访谈纪要
- 会议记录
- 聊天摘录
- 业务流程说明
- 现有 PRD
- 表格、截图、原型说明
- demo 需求清单

默认适用于以下场景：

- 准备写 `01_Question_Input.md`
- 准备写 `02_Competitor_Research.md`
- 准备进入 `03_PRD_Initial.md`
- 准备收口 demo 主线

## 3. Core Goal

本 skill 的核心目标是把输入材料整理成 4 层：

1. 已明确事实
2. 缺失信息
3. 暂时假设
4. 下一步该进入哪份文档

## 4. Intake Order

每次处理输入材料时，严格按以下顺序：

1. 先读已有材料
2. 再提取关键事实
3. 再识别缺口
4. 最后才补问最多 3 个问题

禁止做法：

- 用户已经给了材料，还不读就开始追问
- 明明信息够写一版初稿，却还无限追问细节

## 5. What To Extract

优先提取以下内容：

- 核心角色
- 所在业务环节
- 当前流程卡点
- 目标动作
- 异常或风险点
- 本次版本想证明的价值
- 已明确不做的边界

## 6. Output Structure

输出时使用以下结构：

```markdown
## 输入材料整理卡

### 1. 已明确事实
- 事实 1：
- 事实 2：
- 事实 3：

### 2. 当前缺口
- 缺口 1：
- 缺口 2：

### 3. 暂时假设
- 假设 1：
- 假设 2：

### 4. 建议下一步
- 进入哪份文档：
- 进入原因：
```

## 7. Question Rule

如果必须补问，最多问 3 个问题，优先问：

1. 这次最关键的岗位角色是谁？
2. 当前最核心的流程卡点是哪一步？
3. 这次版本或 demo 最想证明的价值是什么？

问题要求：

- 一次只问一个问题
- 问题必须短
- 问题必须直接服务下一步产出

## 8. Good Output Standard

一份合格的材料整理结果，应该满足：

- 不重复要求用户已经给过的信息
- 能把散乱材料压成清晰的输入摘要
- 能看出哪些内容已经足够写文档
- 能看出哪些问题必须补齐
- 能明确下一步该进入哪个文档阶段

## 9. Next Suggested Actions

完成材料整理后，推荐进入以下任一步：

1. 写入 `01_Question_Input.md`
2. 继续压缩成 `Problem_Definition.md`
3. 进入 `Requirement_Card.md` 或 `Version_Map.md`
