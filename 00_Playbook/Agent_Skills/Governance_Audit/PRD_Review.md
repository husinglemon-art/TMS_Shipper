# PRD Audit Engine

## 1. Purpose

本 skill 用于帮助 **B 端供应链系统产品经理** 在版本收口前，检查 PRD、demo 说明和主档沉淀是否已经达到“可评审、可演示、可继续沉淀”的标准。

它的目标不是机械找错，而是帮助判断：

- 这份 PRD 是否逻辑闭环
- 这份 demo 是否真的在证明业务价值
- 这份主档内容是否适合沉淀
- 哪些问题必须拦截
- 哪些问题可以留作优化建议

## 2. Audit Scope

默认审计对象包括：

- `05_PRD_Final.md`
- `04_Prototype_Notes.md`
- 当前版本的 `Audit_Reports/`
- 需要时对照 `01_Master_Documents/` 中的主档结构
- 默认优先参考 `PRD_Check_Standard/Quick_Check_Rule.md`

## 3. Core Audit Questions

审计时，优先回答以下问题：

1. 角色、场景、动作、结果是否说清楚了？
2. 主流程是否闭环了？
3. 异常处理是否被明确写出来？
4. demo 展示的内容是否真的支撑业务价值？
5. 本次版本边界是否清楚？
6. 是否存在适合沉淀到主档的稳定结论？

## 4. Audit Dimensions

默认优先检查 `Quick_Check_Rule.md` 中定义的 6 个核心维度：

### 4.1 角色与场景

- 是否能明确看出使用角色
- 是否能明确看出发生问题的业务环节

### 4.2 主流程闭环

- 是否能从入口走到结果
- 中间是否存在断层或跳步

### 4.3 异常与边界

- 是否明确写出失败、灰态、不可执行场景
- 是否写清楚本次不做什么

### 4.4 Demo 价值证明

- demo 展示的动作是否能证明业务价值
- 是否只是页面堆叠，而没有业务主线

### 4.5 文档可读性

- 结构是否清晰
- 重点是否明确
- 图和文字是否互相支撑

### 4.6 主档沉淀价值

- 哪些结论已经稳定
- 哪些内容还只是临时讨论，不适合进入主档

## 5. Output Rule

输出时，默认分成两类：

### 5.1 Veto Items

必须拦截的问题，例如：

- 主流程不闭环
- 异常完全没写
- demo 主线失焦
- 角色与场景模糊不清

### 5.2 Guide Items

可继续优化的问题，例如：

- 文案还可以更清楚
- 页面层级还可以更顺
- demo 演示节奏还可以再聚焦

## 6. Output Location

强制输出路径：

- `02_Iteration_Workspace/v[当前版本号]/Audit_Reports/`

生成文件：

1. `check-prd-appendix-veto.md`
2. `check-prd-appendix-guide.md`

## 7. Good Audit Standard

一轮合格的审计，应该满足：

- 能指出必须拦截的问题
- 能区分“必须改”和“建议改”
- 能回到供应链业务闭环，而不是停留在空泛点评
- 能直接指导版本收口和主档沉淀

## 8. Next Suggested Actions

完成审计后，推荐进入以下任一步：

1. 修改 `05_PRD_Final.md`
2. 修改 `04_Prototype_Notes.md`
3. 将稳定结论回填到 `01_Master_Documents/`

## 9. Escalation Reminder

如果当前文档满足以下任一条件，应从快速审查升级为完整检查：

- 准备正式封版
- 准备合并主档
- 已形成完整业务闭环
- 涉及复杂架构、状态流或跨系统依赖
- 需要面向更大范围团队做正式评审

推荐提示语：

> “当前版本已进入复杂版本或正式封版阶段，建议切换到完整检查模式。”

## 10. Human Confirmation Rule

当审查结论会直接影响以下事项时，必须先由人确认，再进入下一步：

- 是否封版
- 是否合并主档
- 是否进入下一阶段
- 是否需要扩大版本范围

建议提醒话术：

> “当前检查结论已足以影响版本走向，建议先由负责人确认，再继续推进。”
