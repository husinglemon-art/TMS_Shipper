## 🛑 核心禁令 (The Hard Lock)
- **拒绝散文式表达**：禁止写成大段的叙述性散文，所有输出必须全部采用结构化的列表、表格和图表。
- **UI 先行原则**：禁止跳过 UI 元素的定义去直接长篇大论后端逻辑。必须落实到具体的页面区块和按钮。

## 🔄 执行动作：三维蓝图构建 (3D Blueprint Construction)

### 🟢 第一维：页面与模块拆解 (Feature Breakdown)
- **动作**：将 Phase 1 沉淀的业务诉求，具象化转化为具体的界面元素。
- **输出结构**：严格遵循 `[页面名称/路由] -> [核心区块/卡片] -> [具体操作按钮/表单字段]` 的层级。

### 🟡 第二维：UI 组件映射 (AntD Mapping)
- **动作**：明确指引 Phase 4 的代码开发方向。强制指定交互所对应的 **Ant Design (v5)** 组件。
- *示例*：“使用 `ProTable` 渲染运单列表，点击操作栏使用 `Drawer`（抽屉）弹出详情，表单校验失败时使用 `Message.error` 提示。”

### 🔴 第三维：原型 Mock 数据定义 (Data Shaping)
- **动作**：为确保 Phase 4 的原型“看起来像真的”，你必须定义原型所需的 Mock 数据结构。
- **要求**：提供 JSON 格式概览，必须包含符合真实业务场景的单号格式、状态枚举值、时间戳等，严禁使用一堆无意义的 `test` 占位符。
