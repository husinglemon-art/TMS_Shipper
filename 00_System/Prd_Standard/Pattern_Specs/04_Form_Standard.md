# ⌨️ Pattern Spec: 录入与编辑标准 (Form Standard)

> **[引用准则]**：涉及 Modal (弹窗)、Drawer (抽屉) 或独立新增/编辑页面时，必须强制执行本标准。AI 必须为每一个字段填充下述“原子属性矩阵”。

---

## 1. 字段原子属性矩阵 (Field Attribute Matrix)
AI 在描述表单时，必须为每个字段补齐以下 7 个维度的定义，严禁漏项：

| 字段名称 | 控件类型 | 录入限制/格式 | 录入长度 (Min/Max) | 超长处理方案 | 默认值 (是否可改) | 枚举值/数据源 (Key:Label) |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| **示例：司机姓名** | `Input` (文本) | 仅限中英文，禁特殊字符 | 2 - 10 字符 | 禁止输入并弹出提示 | 无 | N/A |
| **示例：证件类型** | `Select` (单选) | 必选项 | N/A | N/A | "身份证" (可改) | 0:身份证, 1:护照, 2:驾驶证 |
| **示例：联系电话** | `Input` (数字) | 仅限数字，正则校验手机号 | 固定 11 位 | 无法继续输入 | 无 | N/A |
| **示例：结算币种** | `Radio` (单选) | 必选项 | N/A | N/A | "CNY" (可改) | CNY:人民币, USD:美元 |
| **示例：系统编号** | `Input` (只读) | 自动生成 | 20 字符 | 自动截断 | 自动生成 (不可改) | 后端逻辑生成 |

---

## 2. 录入校验与溢出规则 (Validation & Constraints)

### 2.1 长度与溢出处理逻辑
- **硬限制 (Hard Limit)**：通过 AntD `maxLength` 属性锁定。当用户键入达到最大长度时，输入框应禁止继续输入。
- **溢出警报**：若业务允许输入后再校验，超长部分需标红提示，并显示文案：“内容超出最大长度限制（X/Y）”。
- **即时校验**：用户失去焦点 (`onBlur`) 时，若长度不足或格式不符，必须立即在输入框下方显示红色警告。

### 2.2 默认值与修改权限
- **初始填充**：PRD 必须明确该字段在“新增”和“编辑”态下的默认值。
- **锁定状态**：若字段为“默认且不可修改”（如：单据创建人），组件必须设为 `disabled` 或 `readOnly`，背景色锁定为浅灰色 (#f5f5f5)。

### 2.3 选择器与枚举规范
- **静态枚举**：必须在 PRD 中以 `Key:Value` 形式列出所有选项。
- **动态数据源**：说明该 Select 挂载的 API 接口名称（如：引用 `Driver_List_API`）。

---

## 3. 提交与反馈闭环 (Submission Flow)

### 3.1 提交拦截规则
- **必填强校验**：点击“提交”时，触发全量 `validateFields`。若有报错，页面自动定位至第一个错误项。
- **防重复提交**：
  - 点击按钮后，立即开启 `loading={true}`。
  - 接口返回结果前，按钮保持 `disabled` 状态。

### 3.2 交互结果反馈
- **成功路径**：弹出 `Message.success("数据已成功存入系统")` -> 自动关闭表单容器 -> 触发父级页面数据刷新。
- **失败路径**：弹出 `Notification.error`。若为特定字段冲突（如单号重复），需高亮对应输入框并显示报错原因。

---

## 4. UI 视觉表现规范
- **必填标识**：所有必填项 Label 左侧强制显示 **红色星号 (*)**。
- **对齐方式**：表单 Label 统一右对齐，Input 宽度根据内容长度建议分为 `small(120px)`, `middle(240px)`, `large(100%)`。
