# PRD 快速检查规则

## 1. Purpose

本规则是 `TMS_Shipper` 当前模板工程的默认 PRD 检查入口。

适用目标：

- B 端供应链系统产品经理
- 产品方案试验
- demo 版本收口
- 主档沉淀前的快速审查

说明：
本文件不替代完整的 14 维参考资料，而是提供更适合当前仓库日常使用的轻量检查方法。

## 2. When To Use

优先用于以下文档：

- `01_Question_Input.md`
- `03_PRD_Initial.md`
- `04_Prototype_Notes.md`
- `05_PRD_Final.md`
- `PRD_Master.md`

## 3. Default Check Scope

默认只检查以下 6 个核心维度：

1. 角色与场景
2. 主流程闭环
3. 页面与交互表达
4. 异常与边界
5. demo 主线与版本范围
6. 主档沉淀价值

如果只是一次日常审查，优先做这 6 项，不强制跑完整 14 维。

## 4. Six-Dimension Quick Check

### 4.1 角色与场景

检查点：

- 是否明确写出核心岗位角色
- 是否明确写出业务环节
- 是否明确写出核心场景

典型问题：

- 只有功能，没有角色
- 只有场景，没有任务目标

### 4.2 主流程闭环

检查点：

- 是否能从入口走到结果
- 是否存在断点
- 是否写清楚下一步动作

典型问题：

- 创建后无法继续
- 只写中间步骤，不写起点和终点

### 4.3 页面与交互表达

检查点：

- 页面结构是否清楚
- 交互动作是否明确
- 状态反馈是否可见

典型问题：

- 只有页面名，没有动作说明
- 只有功能名，没有反馈说明

### 4.4 异常与边界

检查点：

- 是否明确写出失败、灰态、异常
- 是否写出本次不做什么
- 是否说明关键边界条件

典型问题：

- 只有正常流
- 范围无限膨胀

### 4.5 Demo 主线与版本范围

检查点：

- demo 是否有清晰主线
- 本次版本必须展示什么
- 本次版本明确不展示什么

典型问题：

- demo 内容堆太多
- 看不出这次版本重点

### 4.6 主档沉淀价值

检查点：

- 哪些内容已经稳定
- 哪些只是临时讨论
- 是否适合回填主档

典型问题：

- 草稿性内容过早进入主档
- 稳定结论没有回填

## 5. Output Format

输出时优先分成两类：

### Veto

必须拦截的问题，例如：

- 角色不清
- 主流程不闭环
- 异常完全没写
- demo 主线失焦

### Guide

可优化的问题，例如：

- 页面层级可再优化
- 文案可再收口
- 版本边界可再明确

## 6. Escalation Rule

只有在以下情况，才建议进入完整 14 维检查：

- 准备做正式封版
- 涉及系统级规划
- 涉及复杂架构、数据建模或商业分析
- 需要做完整质量回顾或方法论评审

### 升级提醒

当出现以下任一情况时，应主动提醒进入复杂版本或正式封版检查阶段：

1. 当前版本准备从 demo 或试验稿进入正式评审
2. 当前文档将被合并进 `01_Master_Documents/`
3. 当前版本已经开始涉及多模块联动、复杂状态流或跨系统依赖
4. 当前版本已经不再只是单点功能，而是完整业务闭环
5. 当前版本需要给更大范围的团队或负责人做正式确认

建议提醒话术：

> “当前版本已超出日常快速检查范围，建议切换到完整检查模式，以确认封版质量。”
