# Customer Journey Mapping

## 1. Purpose

本 skill 用于帮助 **B 端供应链系统产品经理** 画“岗位旅程图”或“demo 路径图”。

它的目标不是做泛 C 端 customer journey，而是帮助你看清：

- 一个岗位角色在流程中从哪里开始
- 中间会经过哪些关键步骤
- 哪一步最容易卡住
- demo 最值得展示哪一段旅程
- 哪些步骤可以简化，哪些步骤必须完整呈现

## 2. Default Context

默认适用于以下背景：

- 你是 B 端供应链系统产品经理
- 研究对象是企业岗位角色，而不是消费者
- 典型角色包括：调度员、仓管、客服、采购、计划、运营、财务
- 旅程通常围绕：登录、接单、分派、运输、入库、出库、异常处理、对账、结算、协同审批

## 3. Core Goal

本 skill 的核心目标是把一段岗位旅程拆成 4 层：

1. 角色从哪里进入
2. 会经过哪些关键步骤
3. 哪些触点决定体验成败
4. 哪段最值得作为 demo 主线

## 4. Required Inputs

使用前尽量明确以下信息：

- 核心岗位角色是谁
- 本次要映射的流程起点和终点是什么
- 当前最痛的摩擦点是什么
- 本次 demo 最想证明的业务价值是什么

如果信息不全，最多补问 3 个问题，优先问：

1. 这次映射的是哪一个岗位角色？
2. 旅程从哪一步开始，到哪一步结束？
3. 这次最想突出解决的摩擦点是什么？

## 6. Writing Rules

- 优先写岗位角色，不写抽象用户
- 优先写流程动作，不写空泛体验词
- 供应链场景下，要特别关注：时效、状态切换、异常、协同、责任边界
- 旅程图不要贪多，先抓一条主线
- 一份岗位旅程图，应能直接服务 PRD 初稿和 demo 主线规划

## 7. Good Output Standard

一个合格的岗位旅程图，应该满足：

- 能明确看出起点、终点和关键步骤
- 能识别出最痛的摩擦点
- 能帮助决定 demo 应该展示什么
- 能支持后续模块拆解和流程图绘制

## 8. Next Suggested Actions

完成岗位旅程图后，推荐进入以下任一步：

1. 合并进 `03_PRD_Initial.md` 的页面拓扑和流程说明
2. 转成 `Demo_Storyline.md` 的 demo 故事线
3. 继续压缩成页面结构与交互清单
