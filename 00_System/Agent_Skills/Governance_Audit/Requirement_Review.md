# ISO29148 To PRD

## 1. Purpose

本 skill 用于帮助 **B 端供应链系统产品经理** 用更务实的方式检查：

- 一份需求文档是不是完整
- 角色和业务目标是不是说清楚了
- 约束、边界、依赖是不是写出来了
- 哪些内容还停留在“想法”，还没变成“需求”

它的目标不是机械套标准条文，而是把 ISO 29148 的“需求完整性”思想，转成适合你们 PM 仓库的检查方法。

## 2. Default Context

默认适用于以下文档：

- `01_Question_Input.md`
- `03_PRD_Initial.md`
- `05_PRD_Final.md`
- `PRD_Master.md`

默认适用于以下场景：

- PRD 初稿是否能继续往下写
- 终稿是否适合收口
- 主档内容是否足够稳定
- demo 范围是否真的支撑业务目标

## 3. Core Goal

本 skill 的核心目标是从 5 个方向检查需求完整性：

1. 角色是否明确
2. 目标是否明确
3. 边界是否明确
4. 约束与依赖是否明确
5. 验收与验证方式是否明确

## 4. Review Checklist

### 4.1 角色与使用场景

- 是否明确写出主要岗位角色
- 是否明确写出发生在哪个供应链环节
- 是否明确写出使用场景

### 4.2 业务目标

- 是否明确写出要解决的问题
- 是否明确写出为什么现在要做
- 是否明确写出成功后的业务价值

### 4.3 范围与边界

- 是否明确写出本次包含什么
- 是否明确写出本次不包含什么
- 是否存在把多个版本目标混在一起的情况

### 4.4 约束与依赖

- 是否写出关键依赖
- 是否写出异常、风险或前置条件
- 是否写出主线成立所依赖的外部条件

### 4.5 验收与验证

- 是否写出如何判断需求已被满足
- 是否写出 demo 该证明什么
- 是否写出仍需验证的假设

## 5. Output Structure

输出时使用以下结构：

```markdown
## 需求完整性检查卡

### 1. 已明确部分
- 已明确 1：
- 已明确 2：
- 已明确 3：

### 2. 缺失部分
- 缺失 1：
- 缺失 2：
- 缺失 3：

### 3. 风险提醒
- 风险 1：
- 风险 2：

### 4. 是否可继续推进
- 当前判断：
- 原因：

### 5. 建议下一步
- 下一步 1：
- 下一步 2：
```

## 6. Writing Rules

- 优先写“是否明确”，不要空泛谈标准
- 优先指出缺口，不复述一整遍文档
- 供应链场景下，要优先检查角色、流程、状态、异常、责任边界
- 如果文档已经足够继续推进，应明确说“可继续”
- 如果文档缺口会影响 demo 或 PRD 收口，应明确标出来

## 7. Good Output Standard

一轮合格的完整性检查，应该满足：

- 能快速指出文档缺口
- 能帮助 PM 判断是否继续推进
- 能把“缺信息”和“低质量表达”区分开
- 能对后续 PRD、demo、主档沉淀产生直接帮助

## 8. Next Suggested Actions

完成完整性检查后，推荐进入以下任一步：

1. 回补 `01_Question_Input.md` 或 `03_PRD_Initial.md`
2. 继续收口 `05_PRD_Final.md`
3. 将稳定内容沉淀到 `PRD_Master.md`
