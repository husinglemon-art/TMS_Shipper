## 6. 核心流程

### 6.1 主流程

```mermaid
flowchart TD
    A[ERP/WMS 同步订单进入工作台] --> B[订单池 / 待规划列表]
    B --> C{是否勾选有效待规划订单}
    C -->|否| C1[停留在列表并提示先勾选订单]
    C -->|是| D[进入运输规划页]
    D --> E[识别订单摘要与关键约束]
    E --> F[给出 FTL 主线结论]
    F --> G[展示 LTL 对照说明]
    G --> H[进入承运商推荐页]
    H --> I[默认按综合评分排序展示候选]
    I --> J{是否存在前程陆运说明场景}
    J -->|否| K[直接比较候选并选择承运商]
    J -->|是| J1[先校验截关时间]
    J1 --> J2[将不满足截关要求的候选降级为风险 / 审计候选]
    J2 --> K
    K --> L[确认指派]
    L --> M[生成运输任务]
    M --> N[展示任务结果与后续入口]
```

### 6.2 异常流程

```mermaid
flowchart TD
    A[异常触发] --> B{异常类型}
    B --> C[订单字段缺失]
    B --> D[订单锁定或规划中]
    B --> E[无协议承运商]
    B --> F[推荐结果过期]
    B --> G[任务生成失败]
    B --> H[批量部分成功]

    C --> C1[阻断进入规划结果区]
    C1 --> C2[高亮缺失项并提示补齐]

    D --> D1[阻断勾选或重复规划]
    D1 --> D2[提示其他调度员处理中]

    E --> E1[进入竞价招标备选分支]
    E1 --> E2[提示人工介入]

    F --> F1[阻断确认指派]
    F1 --> F2[提示刷新结果后重试]

    G --> G1[保留当前指派上下文]
    G1 --> G2[提示失败原因与重试方式]

    H --> H1[拆分成功与失败结果]
    H1 --> H2[展示失败摘要和后续建议]
```

异常流程说明：

- 若订单关键字段缺失，系统必须阻断进入有效规划结果，并在规划页高亮缺失项，引导用户先补齐数据。
- 若订单已处于 `规划中` 或被其他调度员锁定，系统必须阻断重复勾选和重复规划，并明确提示当前由其他人处理中。
- 若无符合条件的协议承运商，系统不应继续沿默认推荐主线推进，而应切换至竞价 / 招标备选分支，或提示人工介入。
- 若推荐结果已过期或被他人更新，系统必须阻断确认指派动作，并要求用户刷新推荐结果后重新确认。
- 若运输任务生成失败，系统需保留当前指派上下文，明确反馈失败原因，并提供重试或人工处理入口。
- 若批量指派出现部分成功、部分失败，系统需拆分展示成功结果和失败摘要，避免只给出笼统失败提示。

## 7. 状态视图

```mermaid
stateDiagram-v2
    [*] --> 待规划
    待规划 --> 规划中 : 调度员进入规划页
    规划中 --> 待确认指派 : 已生成推荐结果或竞价结果
    待确认指派 --> 已指派 : 调度员确认承运商
    已指派 --> 任务已生成 : 系统生成运输任务
    规划中 --> 异常中断 : 关键信息缺失 / 无有效方案
    异常中断 --> 规划中 : 补齐数据后重新规划
    待确认指派 --> 规划中 : 返回调整方案
```

## 8. 外部依赖

| 依赖对象 | 类型 | 作用 | 风险说明 |
| :--- | :--- | :--- | :--- |
| ERP | 外部业务系统 | 提供待规划订单来源 | 订单同步时效和字段完整性 |
| WMS | 外部业务系统 | 提供仓储侧发货需求来源 | 发货状态与字段一致性 |

## 9. 架构约束

- 约束 1：只服务货主侧调度员，不扩货代 / 承运商独立后台。
- 约束 2：前程陆运仅作为说明性支线，优先停留在承运商推荐页的规则说明与候选降级逻辑中。
- 约束 3：被规则拦截的候选可保留为风险或审计候选，但不得与默认推荐候选平级。
